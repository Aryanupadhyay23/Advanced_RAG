Maximal Marginal Relevance (MMR)

The classic algorithm to balance query relevance and document diversity – core to reducing redundancy in retrieval‑augmented generation.

1. Core Idea

  • What is MMR? A greedy re‑ranking algorithm that selects documents one by one, each time picking the document that maximises a combination of relevance to the query and dissimilarity to documents already selected. It mitigates the problem where top‑$k$ similarity results are near‑duplicates.
  • Why does it exist? In information retrieval and RAG, feeding a language model multiple nearly identical chunks wastes context window and provides no new information. MMR diversifies the retrieved set, ensuring each added document contributes unique content.
  • Key trade‑off: Controlled by a single scalar parameter $\lambda$ (lambda): $\lambda=1$ gives pure relevance ranking; $\lambda=0$ gives maximum diversity (almost no regard for query). Typical values lie in $[0.5, 0.8]$.
  • Origin: Introduced by Carbonell & Goldstein (1998) for text summarisation and information retrieval. Now widely used in RAG pipelines, recommendation systems, and search result diversification.

2. Mathematical Formula

Let $D$ be the candidate pool (e.g., top‑$N$ documents from an initial similarity search). Let $S$ be the set of already selected documents, initially empty. For each candidate document $d \in D \setminus S$, the MMR score is:

$ \text{MMR}(d) = \lambda \cdot \text{sim}_1(d, q) \;-\; (1-\lambda) \cdot \max_{d' \in S} \text{sim}_2(d, d') $

$q$: query vector. $\text{sim}_1(d, q)$: relevance similarity (e.g., cosine between document and query). $\text{sim}_2(d, d')$: redundancy similarity (e.g., cosine between document and an already‑selected document $d'$). $\max_{d' \in S}$ penalises the document by its highest similarity to any previously selected one. $\lambda \in [0,1]$ balances the two terms.

The document that achieves the highest MMR score is added to $S$. This process repeats until $k$ documents are selected.

🔍 Interview: “Why the max? Because a single highly similar already‑selected document is enough to make a new document redundant – we need to penalise the worst redundancy.”

3. Greedy Selection Algorithm

1. RETRIEVE INITIAL CANDIDATES: Perform a similarity search (e.g., cosine) to obtain a pool $D$ of $N$ documents (typically $N > k$, e.g., $N = 2k$ to $10k$).
2. INITIALISE: Selected set $S \leftarrow \emptyset$.
3. FOR $i = 1$ to $k$:
   a. For each candidate $d \in D \setminus S$, compute $\text{score}(d) = \lambda \cdot \text{sim}_1(d, q) - (1-\lambda) \cdot \max_{d' \in S} \text{sim}_2(d, d')$.
   b. Select $d^* = \arg\max_{d \in D \setminus S} \text{score}(d)$.
   c. Add $d^*$ to $S$.
4. RETURN $S$ (the $k$ diversified, relevant documents).

Complexity: $O(k \cdot N \cdot |S|)$ similarity computations, which becomes $O(k^2 N)$ if $|S|$ grows to $k$. For small $k$ (e.g., 5‑20), it’s manageable. For larger $k$, optimisations are needed (e.g., pre‑compute pairwise similarities).

4. The Role of Lambda ($\lambda$)

1.0Pure relevance: identical to top‑$k$ similarity ranking. No diversity penalty.When the candidate pool is already naturally diverse, or $k$ is very small.
0.8 – 0.9Strong relevance, mild diversity. Prevents extreme duplicates (exact near‑copies) but keeps highly related content.Standard RAG where some topical overlap is acceptable, but exact duplicate chunks should be avoided.
0.5 – 0.7Balanced relevance and diversity. Ensures retrieved documents cover different sub‑topics or aspects.Multi‑document QA, summarisation, or when the generator benefits from diverse perspectives.

In practice, $\lambda$ should be tuned on a validation set with a metric that balances answer correctness and context utilisation.

5. Geometric Intuition

🔹 The “Cluster Skipper”

Imagine document vectors as points in space, with clusters representing similar topics. MMR first picks the point closest to the query. Then it penalises points near that chosen one, effectively jumping to a new cluster. It continues until $k$ points from different clusters are selected, ensuring coverage of the space rather than crowding in one dense region.

🔹 The “Greedy Frontier”

At each step, MMR draws a frontier: the candidate that offers the best trade‑off between moving towards the query (relevance) and moving away from already‑selected points (diversity). It’s like a hiking path that heads in the general query direction but always tries to explore new ground.

7. Variants & Extensions of MMR

  • Scaled MMR: Normalise the relevance and diversity terms by their standard deviations before combining, to balance their dynamic ranges. This avoids one term dominating when the score distributions differ greatly.
  • Soft MMR: Instead of $\max$, use an average or a soft‑max aggregation of similarities to already‑selected documents, providing a smoother penalty.
  • Adaptive $\lambda$: Start with high $\lambda$ for the first few selections (to guarantee relevance) and gradually decrease $\lambda$ to increase diversity as the set grows.
  • Query‑specific MMR: Adjust $\lambda$ per query based on its ambiguity. For ambiguous queries, increase diversity (lower $\lambda$).
  • MMR with constraints: Enforce that selected documents come from different sources, sections, or timestamps, using metadata filters on top of MMR.

9. Advantages & Limitations

✅ Advantages

  • Simple, intuitive, and easy to implement.
  • Single parameter $\lambda$ provides a smooth trade‑off.
  • Effectively reduces redundancy and improves context coverage.
  • Works with any similarity metric and any embedding space.
  • Incremental (greedy) selection allows early stopping.
  • Interpretable: you can examine why a document was chosen or not.

❌ Limitations

  • Greedy selection is sub‑optimal; the global optimum of a set diversity function is not guaranteed.
  • Computationally expensive for large $k$ or $N$ due to pairwise similarity calculations.
  • Sensitive to the choice of similarity function; different metrics yield different selections.
  • May not handle cases where the relevant documents are naturally all similar (e.g., one topic with many facets) – diversity can hurt by excluding useful context.
  • Requires tuning $\lambda$ on a representative validation set; fixed $\lambda$ may not work for all queries.

10. Practical Implementation Tips

  • Pre‑compute document‑to‑document similarities if the candidate pool is small and static; this significantly speeds up the max‑penalty computation.
  • Use a fast approximate similarity search (e.g., FAISS with inner product) to get the top‑$N$ candidates, then apply MMR as a post‑processing step.
  • Normalise vectors to unit length so that cosine similarity and dot product coincide, simplifying the penalty term.
  • Set $N$ generously (e.g., 5‑10 times $k$) to give MMR enough room to find diverse, relevant documents.
  • Combine with a score threshold – first filter out documents below a relevance threshold, then apply MMR on the remainder. This prevents MMR from selecting marginally relevant but diverse documents.
  • In LangChain: vectorstore.max_marginal_relevance_search(query, k, fetch_k=N, lambda_mult=λ) directly implements MMR using cosine similarity.

11. Interview Questions

Q1: What problem does MMR solve that simple top‑$k$ similarity search does not?

A: Top‑$k$ may return multiple highly similar chunks (e.g., consecutive paragraphs). MMR reduces redundancy by selecting documents that are both relevant to the query and dissimilar to each other, providing broader context for the generator.

Q2: Write down the MMR formula and explain each term.

A: $\text{MMR}(d) = \lambda \cdot \text{sim}_1(d,q) - (1-\lambda) \cdot \max_{d' \in S} \text{sim}_2(d,d')$. $\text{sim}_1(d,q)$ measures relevance to the query. $\text{sim}_2(d,d')$ measures redundancy against already‑selected document $d'$. The $\max$ penalises the worst redundancy. $\lambda$ balances the two.

Q3: How would you choose the value of $\lambda$ for a RAG system that answers factual questions from a knowledge base?

A: Start with $\lambda=0.8$ to keep relevance dominant while removing exact duplicates. Evaluate the end‑to‑end answer accuracy and diversity of retrieved chunks. Adjust upwards if answers become incomplete (missing key facts), or downwards if the generator is overwhelmed by redundant information.

Q4: Explain the greedy selection algorithm of MMR. Why is it greedy, and what is its complexity?

A: It iteratively picks the best document according to the MMR score, adding it to the selected set, and recomputes scores for remaining candidates. It is greedy because it makes a locally optimal choice at each step without considering the global combination. Complexity is $O(k \cdot N \cdot |S|)$ where $|S|$ grows to $k$, so $O(k^2 N)$.

Q5: Can MMR be applied without an initial similarity search? Why or why not?

A: No. MMR is a re‑ranking algorithm that operates on a candidate pool. Applying it directly to millions of vectors would be computationally infeasible because it requires pairwise similarities. Always fetch a top‑$N$ candidate set first via ANN.

12. Common Mistakes

❌ Wrong Belief✅ Correct Understanding
"MMR always improves retrieval performance."If the relevant documents are naturally similar (e.g., multiple chunks from the same critical paragraph), MMR may drop important context, hurting accuracy. It must be evaluated on the task.
"Using $\lambda=0.5$ is always a safe balance."The optimal $\lambda$ depends on the embedding model, the document set, and the query type. Blindly using 0.5 may sacrifice too much relevance.
"The max penalty only considers one previously selected document."Yes, MMR uses the maximum similarity to any selected document, not an average. This makes it sensitive to a single highly redundant document – which is usually the intended behaviour.
"MMR can replace the initial retrieval step."It is a post‑processing step; you still need an efficient ANN search to obtain the candidate pool.
"The same similarity metric must be used for both relevance and diversity."While common, you could use different metrics (e.g., cosine for relevance, Euclidean for diversity) if it better captures the notion of redundancy in your domain.

13. Exam Cram Facts (Day‑Before Revision)

  1. MMR = Maximal Marginal Relevance – a greedy re‑ranking algorithm for diversity.
  2. Core formula: $\text{MMR}(d) = \lambda \cdot \text{sim}(d,q) - (1-\lambda) \cdot \max_{d' \in S} \text{sim}(d,d')$.
  3. $\lambda=1$: pure relevance. $\lambda=0$: pure diversity. Typical range: $0.5$–$0.8$.
  4. Algorithm: start with top‑$N$ candidates, greedily pick $k$ documents maximising MMR.
  5. Complexity: $O(k^2 N)$ similarity computations; efficient for small $k$.
  6. Reduces redundancy in RAG context; improves information coverage.
  7. Not a replacement for initial retrieval; requires a candidate pool.
  8. Sensitive to $\lambda$ and similarity metric; requires tuning.
  9. Variants: scaled MMR, soft MMR, adaptive $\lambda$, constraint‑based MMR.
  10. Widely available in libraries: LangChain, LlamaIndex, custom implementations.
