Document Loaders

Ingesting data from diverse sources – PDFs, web pages, databases, and more – into LLM‑ready text chunks.

1. Core Idea

  • What are they? Document loaders are connectors that read data from a variety of file formats and data sources, extract raw text and metadata, and return a standardized list of Document objects ready for chunking and embedding.
  • Why are they needed? LLM applications (especially RAG) require text content from many heterogeneous sources (PDFs, web pages, databases, etc.). Document loaders abstract away the complexity of parsing different formats.
  • Key abstraction: Every loader returns a list of Document objects, where each document has page_content (text) and metadata (source, page number, etc.). This provides a uniform interface for downstream processing.
  • Common libraries: LangChain, LlamaIndex, Unstructured.io – each provides dozens of pre‑built loaders for specific data types.

2. Types of Document Loaders

2.1 File‑Based Loaders (Local & Cloud)

FormatLoaderKey Features / ParametersCommon Challenges
PDF PyPDFLoader, PDFMinerLoader, UnstructuredPDFLoader Extract text page‑by‑page; metadata includes page number. Can handle selectable text, but not scanned images (OCR required). Complex layouts (tables, columns), embedded images, scanned PDFs need OCR (e.g., UnstructuredImagePDFLoader + Tesseract).
CSV CSVLoader Loads each row as a separate document; column values are concatenated or accessible via metadata. Optionally specify delimiter, encoding. Large CSVs can produce many small documents; may need aggregation or metadata filtering.
Text / Markdown TextLoader, UnstructuredMarkdownLoader Simple file read; preserves formatting. Markdown loader can split by headers or sections. Minimal; encoding issues (UTF‑8 vs others).
JSON / JSONL JSONLoader, JSONLinesLoader Extract content from specific keys using JSON pointer (e.g., /content); metadata from other fields. Nested structures need careful jq‑style specification; arrays may be flattened.
HTML UnstructuredHTMLLoader, BSHTMLLoader Strips HTML tags and extracts plain text; optionally retains structure (titles, paragraphs). Dynamic pages (JavaScript‑rendered) require headless browser (e.g., Playwright/Selenium).
Word / PowerPoint Docx2txtLoader, UnstructuredWordDocumentLoader, UnstructuredPowerPointLoader Extracts text from Office documents; preserves headings, bullet points, and slide structure. Embedded objects (charts, images) are ignored; text ordering can be complex.
Images (OCR) UnstructuredImageLoader (with Tesseract or cloud OCR) Optical Character Recognition on images; returns extracted text. Requires additional dependencies. Accuracy depends on image quality; multiple languages; layout detection (tables).

3. Key Concepts & Common Parameters

ConceptDescriptionExample
MetadataEach loaded document carries a metadata dict with source info (filename, page, URL, creation date). Used later for citation, filtering, and deduplication.{"source": "annual_report.pdf", "page": 5}
EncodingSpecify text encoding (UTF‑8, Latin‑1) to avoid garbled characters. Most loaders accept an encoding parameter.TextLoader("file.txt", encoding="utf-8")
Lazy LoadingSome loaders support lazy loading, yielding documents one at a time instead of loading everything into memory. Ideal for very large datasets.loader.lazy_load()
File FilteringGlob pattern or function to include/exclude files when loading directories.glob="**/*.pdf", exclude=["*.tmp"]
Mode / StrategyFor PDFs, choose between "single" (entire file as one doc), "page" (each page separate), or "elements" (per paragraph/table). Provided by Unstructured library.mode="elements"

5. Common Challenges & Best Practices

ChallengeBest Practice
Multi‑format ingestionUse Unstructured library or a factory pattern; detect file type by extension and route to appropriate loader.
Very large filesUse lazy loading; stream documents to a queue; avoid loading entire dataset into memory.
Scanned PDFs / imagesUse OCR‑enabled loaders (Unstructured + Tesseract). Pre‑process images (deskew, denoise) for better accuracy.
Dynamic web contentFor JS‑heavy pages, use a headless browser loader (Playwright, Selenium) instead of simple HTTP fetch.
Structured data (tables)Convert tables to text descriptions or use dedicated table parsers; consider adding row/column metadata.
DeduplicationUse content hash or document ID stored in metadata; filter duplicates before chunking.
AuthenticationStore API keys / tokens securely (environment variables, vaults); never hardcode.
Rate limiting (APIs)Implement retry with exponential backoff; respect rate limits to avoid bans.

6. Interview Questions

Q1: What is the role of a document loader in a RAG pipeline?

A: It reads raw data from various sources (PDF, web, DB) and converts it into a standardized list of Document objects (text + metadata) that can be chunked, embedded, and indexed for retrieval.

Q2: How would you handle a PDF with complex tables and images?

A: Use a loader like UnstructuredPDFLoader with mode="elements" which segments text into paragraphs, tables, and figures. For tables, use a dedicated table parser (e.g., Camelot, Tabula) or capture as CSV. For images, use OCR.

Q3: What is lazy loading and when is it useful?

A: Lazy loading yields documents one at a time instead of loading all into memory at once. It’s crucial when dealing with very large datasets (e.g., millions of rows in a CSV) to avoid out‑of‑memory errors.

Q4: How do you ensure that a web page’s dynamic content is captured?

A: Use a browser‑based loader like PlaywrightURLLoader or SeleniumURLLoader which render JavaScript. For single‑page apps, wait for specific elements to appear before extracting text.

Q5: What metadata should you include in documents, and why?

A: Include source (file path/URL), page number (for PDF), creation date, author, and any domain‑specific tags. Metadata enables filtering, citation, and better retrieval relevance.

7. Common Mistakes

❌ Wrong Practice✅ Correct Approach
Using a simple text loader for PDFs.Use a PDF‑aware loader (PyPDFLoader, PDFMinerLoader) to preserve page structure and metadata.
Ignoring encoding issues; assuming UTF‑8.Always specify encoding or use chardet to detect encoding automatically.
Loading everything into memory at once for large datasets.Use lazy loading and stream documents; process in batches.
Not extracting metadata (e.g., source, page).Leverage the loader’s built‑in metadata extraction; enrich with custom fields for filtering.
Using a generic web loader for authentication‑protected pages.Use loaders that accept cookies, headers, or OAuth tokens (WebBaseLoader with session).

8. Exam Cram Facts (Day‑Before Revision)

  1. Document loaders abstract data ingestion, returning Document objects (text + metadata).
  2. Common loaders: PyPDFLoader (PDF), CSVLoader (CSV), TextLoader, UnstructuredHTMLLoader, JSONLoader.
  3. Unstructured library provides mode="elements" for PDFs and rich extraction of tables, titles, etc.
  4. For scanned PDFs/images, use OCR loaders (e.g., Unstructured + Tesseract).
  5. Web loaders: WebBaseLoader (static), PlaywrightURLLoader (dynamic).
  6. Lazy loading avoids memory issues with huge files.
  7. Always capture metadata: source, page, date, author → enables filtering and citation.
  8. Authentication for cloud loaders: use environment variables, not hardcoded keys.
  9. Standard pipeline: Load → (Clean) → (Enrich metadata) → Chunk → Embed → Index.
  10. A single loader may not cover all formats; use a factory pattern to route based on file extension.
