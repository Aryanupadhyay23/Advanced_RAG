BM25

Best Match 25 – the classic probabilistic bag‑of‑words retrieval function, balancing term frequency, inverse document frequency, and document length normalization.

1. Core Idea

  • What is BM25? A ranking function that estimates the relevance of documents to a given query based on exact keyword matching. It is the de‑facto standard for sparse lexical retrieval (full‑text search), used in Lucene, Elasticsearch, and hybrid RAG systems.
  • Why does it exist? Early TF‑IDF methods over‑emphasised rare terms and long documents. BM25 introduces term frequency saturation (diminishing returns for repeated terms) and tunable document length normalization, providing a more robust relevance score.
  • Core principle: Each query term contributes a weight equal to its IDF (inverse document frequency) multiplied by a dampened term frequency factor. The scores are summed across all query terms.
  • Key advantage over embeddings: Exact lexical matching; no need for training; completely transparent; works out‑of‑the‑box without an embedding model.

2. Mental Model

🔹 The “Librarian’s Card Catalog”

BM25 is like a librarian who, given a list of words, looks them up in a card catalog. Rare words (like “hippopotamus”) are very informative and get high weight; common words (like “the”) are ignored. The librarian also compensates for book thickness – a 200‑page book that mentions a word once is more relevant than an 800‑page book mentioning it once.

🔹 The “Saturation Curve”

Repeating a keyword helps, but only up to a point. Saying “cat” 100 times doesn’t make a document 100× more relevant about cats than saying it 5 times. BM25’s TF component saturates – after a few occurrences, extra mentions add little extra score.

3. Key Concepts

ConceptMeaningImportanceInterview Insight
Term Frequency (TF) How many times a query term appears in a document. In BM25, it’s not linear – it saturates: $ \frac{f \cdot (k_1+1)}{f + k_1 \cdot (1 - b + b \cdot \frac{|d|}{\text{avgdl}})} $. Captures the intuition that more mentions mean higher relevance, but with diminishing returns. “Why saturate? Because after 3‑4 mentions, the document is already about the topic; more mentions shouldn't double the score.”
Inverse Document Frequency (IDF) Measures how rare a term is across the entire collection: $ \text{IDF}(t) = \log\left( \frac{N - n(t) + 0.5}{n(t) + 0.5} + 1 \right) $, where $N$ is total docs, $n(t)$ is number of docs containing $t$. Gives high weight to discriminative terms and low weight to stop words. “The Robertson‑Spärck Jones IDF is a smoothed version that avoids division by zero and negative values.”
Document Length Normalization Adjusts TF based on document length relative to the average length ($\text{avgdl}$). Controlled by parameter $b$. Short documents with a term are favoured over long documents with the same TF. Prevents long documents from dominating simply because they contain more words. “Parameter $b$ controls how much length matters: $b=1$ full normalization, $b=0$ no normalization.”
Parameters $k_1$ and $b$ $k_1$: controls TF saturation rate (typical 1.2–2.0). $b$: controls document length normalization strength (typical 0.75). Make BM25 tunable to specific collections; no training required, just heuristics. “$k_1=1.2$ is a common default; $b=0.75$ works well for most text. For very short or very long documents, tweak $b$.”

4. Formula Sheet

4.1 BM25 Score for a Query $q$ and Document $d$

$ \text{BM25}(q, d) = \sum_{t \in q} \text{IDF}(t) \cdot \frac{ f(t,d) \cdot (k_1 + 1) }{ f(t,d) + k_1 \cdot \left(1 - b + b \cdot \frac{|d|}{\text{avgdl}} \right) } $

$t$: a term (word) in the query. $f(t,d)$: frequency of term $t$ in document $d$. $|d|$: length of document $d$ (number of terms). $\text{avgdl}$: average document length in the collection. $k_1$: TF saturation parameter. $b$: length normalization parameter.

4.2 IDF (Robertson‑Spärck Jones)

$ \text{IDF}(t) = \log \left( \frac{ N - n(t) + 0.5 }{ n(t) + 0.5 } + 1 \right) $

$N$: total number of documents in the collection. $n(t)$: number of documents containing term $t$. The +0.5 and +1 provide smoothing.

4.3 Interpretation of the TF Component

When $f(t,d) \ll k_1 \cdot (\ldots)$: score grows almost linearly with $f$.
When $f(t,d) \gg k_1 \cdot (\ldots)$: score approaches $k_1+1$ asymptotically – saturation.

4.4 Default Parameters

$k_1 = 1.2 \quad\text{(range 1.2–2.0)}$
$b = 0.75 \quad\text{(range 0–1)}$

These values are widely used in Lucene/Elasticsearch and most BM25 implementations.

5. Retrieval Workflow with BM25

1. INDEXING: For each document in the collection, build an inverted index mapping each term to its document IDs and term frequencies. Compute document lengths and average document length.
2. QUERY PROCESSING: Tokenize the query; optionally remove stop words or apply stemming (depending on implementation).
3. FOR EACH QUERY TERM $t$:
   a. Look up $t$ in the inverted index to get all documents containing $t$ and their term frequencies.
   b. Compute $\text{IDF}(t)$ using the collection statistics.
   c. For each document $d$ containing $t$, compute the BM25 term contribution.
4. AGGREGATE: For each candidate document, sum the contributions from all query terms that appear in it.
5. RANK: Sort documents by total BM25 score in descending order; return top‑$k$.

Complexity: Linear in the number of documents containing at least one query term. Highly efficient with an inverted index; can scale to billions of documents.

7. BM25 Variants

  • BM25F: Extension for structured documents with multiple fields (title, body, abstract). Each field has its own length and a weight; term frequencies are combined across fields.
  • BM25+: Adds a small constant to the TF component to avoid the zero‑score problem for terms that appear in very few documents.
  • BM25L: Adjusts the length normalization to be asymmetric for very short and very long documents.
  • Lucene’s Practical BM25: Uses a slightly modified IDF formula and term‑level boosts; the basis for Elasticsearch’s default similarity.

8. BM25 in RAG & Hybrid Search

  • Sparse retriever: BM25 retrieves documents based on exact keyword matches, complementing dense embeddings which capture semantic similarity.
  • Hybrid search: Combine BM25 scores with vector similarity scores (e.g., via reciprocal rank fusion or linear combination). This captures both lexical and semantic relevance.
  • When BM25 shines: Queries containing rare, specific terms (e.g., error codes, technical jargon, entity names) where dense models may fail to retrieve the exact match.
  • When dense retrieval shines: Paraphrasing, synonyms, concept‑based queries. Hybrid approaches combine both strengths.
  • Implementation: Libraries like rank_bm25 (Python), Elasticsearch’s built‑in BM25, or Weaviate’s hybrid search parameter.

9. Advantages & Limitations

✅ Advantages

  • Fast, interpretable, and needs no training – just indexing.
  • Excellent for exact keyword matching; handles rare terms well.
  • Robust across domains without fine‑tuning.
  • Lightweight; runs efficiently even on CPU with an inverted index.
  • Easy to combine with dense retrieval for hybrid systems.
  • Well‑understood theoretical foundations in probabilistic information retrieval.

❌ Limitations

  • No semantic understanding; misses synonyms and paraphrases (the “vocabulary mismatch” problem).
  • Treats documents as bags‑of‑words; ignores word order and proximity.
  • Cannot handle multi‑word concepts or cross‑referencing between terms.
  • Performance degrades for very short queries (few discriminative terms).
  • Sensitive to tokenization and language‑specific preprocessing.
  • Document length normalization can overly penalise long but highly relevant documents.

10. Interview Questions

Q1: Explain the BM25 scoring formula. What do the parameters $k_1$ and $b$ control?

A: $\text{BM25}(q,d) = \sum_{t \in q} \text{IDF}(t) \cdot \frac{f \cdot (k_1+1)}{f + k_1(1-b + b \cdot |d|/\text{avgdl})}$. $k_1$ controls how quickly term frequency saturates; $b$ controls how much document length is penalised (0 = no penalty, 1 = full normalization).

Q2: How does BM25 handle term frequency differently from classic TF‑IDF?

A: Classic TF‑IDF uses raw or log‑normalized term frequency without saturation; an additional occurrence always increases the score. BM25 saturates TF, so after a few occurrences extra mentions add little weight. This prevents term‑stuffing from boosting documents artificially.

Q3: Why is BM25 often used alongside dense embeddings in a hybrid RAG system?

A: Dense embeddings excel at semantic understanding but may miss exact keyword matches (e.g., product codes, rare technical terms). BM25 guarantees that if the exact word appears, it will be found. The combination ensures both recall and precision.

Q4: How would you tune BM25 for a domain with very long documents (e.g., legal contracts)?

A: Increase $b$ to more heavily penalise length, preventing long documents from dominating. Possibly also increase $k_1$ to allow longer documents to benefit from repeated important terms. Evaluate on domain‑specific relevance judgments.

Q5: What are the limitations of BM25, and how do modern dense retrievers address them?

A: BM25 suffers from vocabulary mismatch – it cannot match synonyms or paraphrases. Dense retrievers embed queries and documents into a semantic space where similar meanings are close, overcoming this limitation. However, dense retrievers require training data and are less interpretable.

11. Common Mistakes

❌ Wrong Belief✅ Correct Understanding
"BM25 is just TF‑IDF with different constants."It introduces TF saturation and length normalization, making a significant practical difference. Without saturation, a word appearing 100 times would give 100× the score, which is unrealistic.
"$k_1=0$ means TF is ignored."$k_1=0$ gives a constant score for any non‑zero TF (the fraction becomes 1), not zero. Setting $k_1$ very small heavily dampens TF but still rewards presence.
"BM25 requires IDF training."IDF is computed directly from collection statistics; no iterative training needed. It is a ranking function, not a machine learning model.
"BM25 only works for English."BM25 is language‑agnostic as long as there is a tokenizer for that language. It relies on term statistics, not linguistic features.
"BM25 cannot be used with large $k$ for hybrid search."It scales well; with an inverted index, retrieving top‑1000 BM25 candidates is fast. It's commonly used as the first stage in a multi‑stage retrieval pipeline.
