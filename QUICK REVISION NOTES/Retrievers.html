Retriever Techniques

Similarity‑Based Search, Maximal Marginal Relevance (MMR), and Threshold‑Based Retrieval – controlling relevance and diversity.

1. Core Idea

  • What is a Retriever? The component that, given a query embedding, fetches the most relevant document chunks from a vector store. It defines how similarity is computed and which results are ultimately passed to the generator.
  • Why do retrieval strategies matter? Naive similarity search can return redundant, near‑identical chunks. MMR adds diversity. Threshold‑based retrieval prevents low‑quality context from entering the prompt. Together they control the relevance, diversity, and quality of the retrieved context.
  • Key retrieval patterns:
    • Similarity‑Based Search: Return top‑$k$ chunks ranked by cosine similarity (or dot product) to the query.
    • MMR (Maximal Marginal Relevance): Re‑rank candidates to balance relevance against novelty, avoiding redundancy.
    • Threshold‑Based: Filter out chunks whose similarity score is below a minimum threshold; ensures only sufficiently relevant context is used.

2. Similarity‑Based (Semantic) Search

2.1 How It Works

  1. Embed the user query $\mathbf{q}$ using the same embedding model used for the document chunks.
  2. Compute the similarity score $s(\mathbf{q}, \mathbf{d}_i)$ for every document vector $\mathbf{d}_i$ in the vector store (e.g., cosine similarity).
  3. Sort documents in descending order of similarity.
  4. Return the top‑$k$ documents (or all documents above a threshold, depending on configuration).

2.2 Score Functions

MetricFormulaRangeNotes
Cosine Similarity$ \text{sim}(\mathbf{q}, \mathbf{d}) = \frac{\mathbf{q} \cdot \mathbf{d}}{\|\mathbf{q}\| \|\mathbf{d}\|} $$[-1,1]$ (typically $[0,1]$ for modern embeddings)Default in most RAG systems; magnitude‑invariant.
Dot Product$ \text{sim}(\mathbf{q}, \mathbf{d}) = \mathbf{q} \cdot \mathbf{d} $$(-\infty, \infty)$Equivalent to cosine if vectors are $L^2$ normalized. Simpler, faster.
Euclidean Distance$ d(\mathbf{q}, \mathbf{d}) = \|\mathbf{q} - \mathbf{d}\| $$[0, \infty)$Often converted to similarity via negative distance or exponential kernel.

2.3 Limitations of Pure Similarity Search

  • Redundancy: Top‑$k$ results may be very similar to each other (e.g., multiple chunks from the same paragraph), wasting context window.
  • No quality gating: Even low‑similarity results are returned if $k$ is larger than the number of relevant documents.
  • Sensitive to embedding model quality: Poor embeddings → poor retrieval.

3. Maximal Marginal Relevance (MMR)

3.1 Concept

MMR is a re‑ranking algorithm that selects documents iteratively, balancing relevance to the query and dissimilarity to already‑selected documents. It reduces redundancy by penalising candidates that are too similar to already‑chosen ones.

3.2 Algorithm (Greedy Selection)

  1. Retrieve an initial pool of $N$ candidates (e.g., top‑$N$ by similarity, with $N > k$).
  2. Initialize the set of selected documents $S = \emptyset$.
  3. For $i = 1$ to $k$:
    • For each candidate $\mathbf{d}$ not yet in $S$, compute the MMR score:
$ \text{MMR}(\mathbf{d}) = \lambda \cdot \text{sim}(\mathbf{d}, \mathbf{q}) \;-\; (1 - \lambda) \cdot \max_{\mathbf{d}' \in S} \text{sim}(\mathbf{d}, \mathbf{d}') $

$\lambda \in [0,1]$: diversity parameter. $\lambda=1$ → pure relevance; $\lambda=0$ → pure diversity. $\text{sim}(\mathbf{d}, \mathbf{q})$ is relevance to query; $\text{sim}(\mathbf{d}, \mathbf{d}')$ is similarity to an already‑selected document (redundancy penalty).

The candidate with the highest MMR score is added to $S$. This repeats until $k$ documents are selected.

3.3 Hyperparameters

ParameterEffectTypical Range
$\lambda$ (lambda)Higher → favour relevance; Lower → favour diversity.0.5 – 0.8
Fetch size ($N$)Number of initial candidates to consider. Larger $N$ gives MMR more options to balance but increases computation.$2k$ – $10k$

3.4 Advantages & Limitations

  • ✅ Pros: Increases diversity of context; avoids wasting context window on duplicate information; can improve answer completeness.
  • ❌ Cons: Computationally more expensive than top‑$k$ similarity (requires pairwise similarities). Greedy selection may not be globally optimal. Tuning $\lambda$ is domain‑dependent.

4. Threshold‑Based Retrieval

4.1 Concept

Instead of blindly returning the top‑$k$ documents, filter out any document whose similarity score is below a predefined minimum. Only documents that are sufficiently relevant are kept. If fewer than $k$ documents pass the threshold, the generator receives a shorter (or even empty) context.

4.2 Types of Thresholds

TypeHow It WorksUse Case
Score ThresholdAccept documents only if $\text{sim}(\mathbf{q}, \mathbf{d}) \ge \tau$. $\tau$ is a fixed value, e.g., 0.7.When you want to ensure only highly relevant context is used.
Top‑$k$ with Score FloorRetrieve top‑$k$ but then remove any that fall below the threshold.Ensures both quantity ($k$) and quality limits.
Adaptive / Percentile ThresholdUse a threshold based on the score distribution (e.g., top‑10% of scores).Dynamic adjustment for different queries.
Low Relevance FallbackIf no document meets the threshold, return a pre‑defined message or fallback answer instead of forcing poor context.Critical when the knowledge base may not contain the answer.

4.3 Hyperparameters

4.4 Advantages & Limitations

  • ✅ Pros: Prevents low‑quality or unrelated context from confusing the generator. Acts as a safeguard against hallucination.
  • ❌ Cons: A fixed threshold may not work well across diverse queries (some queries naturally have lower similarity scores). If set too high, the retriever may return zero results.

5. Combining Strategies

  • MMR + Threshold: First filter candidates by a score threshold, then apply MMR on the remaining pool to select $k$ diverse, relevant documents. This provides both quality gating and diversity.
  • Similarity + Threshold + Reranker: Retrieve top‑$N$ via similarity, apply a score threshold, then pass candidates through a more expensive cross‑encoder reranker, and finally apply MMR or another selection method.
  • Fallback: If no document meets the threshold, either expand the search (hybrid retrieval, query expansion) or return a safe fallback response.

7. Interview Questions

Q1: Why does pure similarity‑based retrieval often return redundant results?

A: Because the top‑$k$ highest‑scoring chunks may all come from the same section or repeat similar information. Cosine similarity doesn’t penalise similarity among the retrieved documents themselves.

Q2: Explain the MMR formula. What does each term represent?

A: $\text{MMR}(\mathbf{d}) = \lambda \cdot \text{sim}(\mathbf{d}, \mathbf{q}) - (1-\lambda) \cdot \max_{\mathbf{d}' \in S} \text{sim}(\mathbf{d}, \mathbf{d}')$. The first term measures relevance to the query; the second term penalises similarity to already‑selected documents, with $\lambda$ controlling the trade‑off.

Q3: How would you choose the score threshold $\tau$ in a RAG pipeline?

A: By analysing the similarity score distribution of a held‑out set of query‑relevant document pairs. Set $\tau$ to balance precision (avoid false positives) and recall (avoid missing the answer). Often requires iterative tuning; adaptive or per‑query thresholds can be more robust.

Q4: Compare MMR and a simple top‑$k$ approach in terms of computational cost.

A: MMR is more expensive because it requires computing pairwise similarities between candidates and selected documents ($O(k \cdot N)$). Top‑$k$ only sorts one list. For large $N$, MMR can be a bottleneck; optimised implementations or pre‑computed document similarities help.

Q5: What happens if the score threshold is set too high in a RAG system?

A: The retriever may return zero or too few chunks, leading to the LLM receiving an empty or sparse context. This can cause the LLM to refuse to answer or to hallucinate. A fallback mechanism is essential.

8. Common Mistakes

❌ Wrong Belief✅ Correct Understanding
"MMR always improves RAG results."MMR helps when redundancy is a problem; if the top‑$k$ is already diverse, MMR may remove marginally useful but still relevant documents. Tune $\lambda$ and evaluate on your data.
"A score threshold of 0.7 works for every embedding model."Different models produce different score distributions; a fixed threshold must be calibrated per model and dataset.
"If no document passes the threshold, just increase $k$."Increasing $k$ doesn't improve relevance; it just adds more low‑similarity noise. Fix the retrieval pipeline (better embeddings, hybrid search) or accept a fallback.
"MMR can be applied on the full index without an initial similarity fetch."MMR requires a candidate set; running it on millions of vectors is impractical. Always fetch top‑$N$ first.
"Threshold filtering is a replacement for diversity."Threshold ensures quality; MMR ensures variety. They address different aspects and are often combined.

9. Exam Cram Facts (Day‑Before Revision)

  1. Retriever fetches relevant document chunks using similarity, MMR, or threshold strategies.
  2. Similarity search: embed query, compute cosine, return top‑$k$. Fast but may be redundant.
  3. MMR: iteratively selects documents maximising $\lambda \cdot \text{sim}(\mathbf{d}, \mathbf{q}) - (1-\lambda) \max \text{sim}(\mathbf{d}, \mathbf{d}')$. Balances relevance and diversity.
  4. $\lambda = 1$ → pure relevance; $\lambda = 0$ → pure novelty. Typical range 0.5–0.8.
  5. Threshold‑based: only keep documents with similarity score $\ge \tau$. Prevents low‑quality context.
  6. If no document passes threshold → fallback strategy required.
  7. MMR + Threshold: filter by score, then select diverse top‑$k$ from the high‑quality pool.
  8. Complexity: MMR $O(k \cdot N)$ for $N$ candidates; similarity search $O(N \log k)$ with heap or $O(N)$.
