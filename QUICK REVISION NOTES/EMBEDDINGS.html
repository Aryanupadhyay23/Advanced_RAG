Embeddings

Dense vector representations that capture semantic meaning – the mathematical bridge between text and machine learning models.

1. Core Idea

  • What is an embedding? A dense, fixed‑length vector (e.g., 768‑dim) that represents a word, sentence, or document in a continuous vector space. It maps discrete symbols (tokens) to a continuous geometry where semantically similar items are close together.
  • Why does it exist? Machine learning models require numerical input. Embeddings convert text into numbers while preserving semantic relationships – “king” and “queen” are closer than “king” and “table”. This enables similarity search, clustering, and serving as input to neural models.
  • Key property: The distance (cosine, Euclidean) between two embedding vectors reflects their semantic similarity. Embeddings are learned from co‑occurrence statistics or language modeling tasks.
  • In RAG: Embeddings transform user queries and document chunks into vectors, enabling efficient nearest‑neighbour retrieval in a vector database.

2. Mental Model

🔹 The “Semantic Map”

Imagine all words/sentences placed on a huge map. Words with similar meaning (cat, kitten) are clustered together; unrelated words (cat, car) are far apart. Embeddings are the GPS coordinates of meaning – the closer the coordinates, the more similar the content.

🔹 The “Translation Layer”

Computers don’t understand text. Embeddings act as a Rosetta Stone: they translate human language into a numeric form that algorithms can process, while keeping the “meaning” encoded in the spatial arrangement of numbers.

4. Formula Sheet

4.1 Cosine Similarity

cosine(u, v) = (u · v) / (||u|| · ||v||) = Σ ui vi / ( √Σ ui2 · √Σ vi2 )

Range: [‑1, 1]. 1 = perfectly aligned, 0 = orthogonal (no relation), –1 = opposite direction. In practice, embeddings are usually in the positive orthant, so similarity ∈ [0,1].

4.2 Word2Vec (Skip‑gram) Objective

maximize Σt Σ‑c ≤ j ≤ c, j≠0 log P( wt+j | wt )
where P( wO | wI ) = exp( v'wOT · vwI ) / Σw exp( v'wT · vwI )

Predicts surrounding context words given a center word. The weight vectors vwI (input) or v'wO (output) become the word embeddings.

4.3 Sentence‑BERT (Siamese Training)

Loss = MSE( cosine(u, v), gold_similarity )   (regression)
or CrossEntropy over softmax of cosine similarities (classification with multiple sentences).

Fine‑tunes a transformer encoder (e.g., BERT) so that similar sentence pairs have high cosine similarity, and dissimilar pairs low similarity.

7. Role in RAG (Retrieval‑Augmented Generation)

Ingestion: Documents → chunked → each chunk passed through embedding model → vector stored in vector DB.
Querying: User query → embedding model → query vector → nearest‑neighbour search (cosine) in vector DB → retrieve top‑k chunks.
The retrieved chunks are then injected into the LLM prompt as context.

Embedding model choice is critical: ideally, the same model should embed both queries and documents (symmetric) or use a model that distinguishes query vs. document (asymmetric, like Cohere’s input_type).

8. Advantages & Limitations

✅ Advantages

  • Dense, compact representation – efficient storage and computation.
  • Captures semantic meaning; can measure similarity without keyword overlap.
  • Pre‑trained models provide strong generic representations out‑of‑the‑box.
  • Contextual embeddings resolve polysemy.
  • Enables powerful retrieval systems (semantic search, RAG) and clustering.
  • Transferable across tasks – e.g., embeddings pre‑trained on a large corpus can be fine‑tuned for specific domains.

❌ Limitations

  • Static models cannot handle word meaning changes over time or domain‑specific jargon.
  • Training large embedding models is resource‑intensive.
  • Embedding quality depends heavily on training data – biases are inherited.
  • Not interpretable: individual dimensions usually have no clear meaning.
  • Mixing different embedding models (e.g., query and document from different models) can break similarity assumptions.
  • Cosine similarity can be fooled by high‑dimensional noise; calibration needed.

9. Interview Questions

Q1: What is an embedding and why is it essential for NLP?

A: An embedding is a dense vector representing text in a continuous space where semantically similar items are close. It’s essential because ML models require numerical input; embeddings convert text while preserving meaning, enabling similarity comparison, classification, and retrieval.

Q2: Explain the difference between static and contextual embeddings with an example.

A: Static embeddings (Word2Vec) give a single vector per word – “bank” has the same embedding regardless of context. Contextual embeddings (BERT) generate different vectors for “bank” in “river bank” vs “money bank”, capturing polysemy.

Q3: Why is cosine similarity preferred over Euclidean distance for comparing embeddings?

A: Cosine similarity measures the angle between vectors, focusing on direction rather than magnitude. In text, document length shouldn’t affect relevance – a longer document about a topic isn’t inherently more similar. Cosine is invariant to vector length.

Q4: How do Sentence‑BERT models produce sentence embeddings, and why are they better than averaging BERT token embeddings?

A: Sentence‑BERT fine‑tunes BERT with a siamese/triplet structure and a pooling layer (mean of token embeddings) to produce a fixed‑size sentence vector. Averaging BERT token embeddings without fine‑tuning yields poor sentence representations because BERT was not trained for sentence‑level similarity. Sentence‑BERT explicitly trains for that.

Q5: In a RAG system, why might you choose different embedding models for the query and the document?

A: Some models (like Cohere) support asymmetric embeddings – a separate model for queries (shorter, question‑like) and documents (longer, informative). This can improve retrieval because queries and documents have different statistical properties. However, many models (Ada) use symmetric embeddings where the same model handles both.

10. Common Mistakes

❌ Wrong Belief✅ Correct Understanding
“Averaging Word2Vec vectors gives a good sentence embedding.”It ignores word order and context; Sentence‑BERT or dedicated sentence models are far superior.
“Higher cosine similarity always means better match.”Cosine similarity can be high for unrelated but frequently co‑occurring concepts. It should be calibrated with human judgment and combined with other signals (BM25).
“Any embedding model works for any task.”Choose a model trained for the specific task: retrieval models (BGE, E5) outperform general‑purpose models for search. Check MTEB leaderboard.
“Embeddings are just PCA of Bag‑of‑Words.”Modern embeddings are learned via deep neural networks and capture non‑linear semantic relationships far beyond linear methods.
“If the embedding dimension is higher, it’s always better.”Beyond a point, higher dimensions increase compute and storage without significant gain; there is a trade‑off. 768 or 1024 is often sufficient.

11. Exam Cram Facts (Day‑Before Revision)

  1. Embeddings are dense, fixed‑length vectors representing text; similar texts have similar vectors (high cosine similarity).
  2. Cosine similarity formula: cos(u,v) = (u·v) / (||u||·||v||). Range [‑1,1]; typically positive for real embeddings.
  3. Static embeddings (Word2Vec, GloVe) give one vector per word, ignoring context.
  4. Contextual embeddings (BERT, Sentence‑BERT) change with surrounding words – solves polysemy.
  5. Sentence‑BERT fine‑tunes BERT with siamese/triplet training + pooling for sentence‑level embeddings.
  6. Key models for RAG: OpenAI Ada (1536d), Cohere Embed (1024d), BGE, E5, Sentence‑BERT (384d).
  7. In RAG: document chunks → embed → vector DB; query → embed → nearest‑neighbour search → retrieve top‑k.
  8. Asymmetric embeddings: separate models for query and document (Cohere); symmetric: same model (Ada).
  9. Embedding dimension is a trade‑off between richness and efficiency; 384‑1024 common.
  10. MTEB benchmark is the standard for comparing text embedding models.
